Random Variables


26 minutes

So far, events. An event happened or it did not, and we counted. But data is not made of yes/no answers—it is made of numbers, and to reason about numbers we need one more object.

The definition, which is less mysterious than the name

A random variable is a function that assigns a number to each outcome of a random process.

It is not a variable in the programming sense, and it is not random in the sense of “arbitrary”. It is a rule: outcome in, number out. The randomness lives entirely in which outcome occurs; the function itself is completely deterministic.

Once you read the phrase as “function of a random outcome”, most of the confusion around the term disappears.

Roll two dice. The outcome is a pair like (6, 1). From that one outcome you can compute many different numbers, and each rule is a different random variable:

X = \text{the sum}, \qquad Y = \text{how many sixes appeared}

One column of outcomes, two columns of numbers computed from them. d1 + d2 is the function; X is what it returns. Notice that (d1 == 6) + (d2 == 6) adds two TRUE/FALSE values as 1 and 0—an event is a random variable that only takes the values 0 and 1, which is why the mean() trick has been working all along.

Notation. Capital letters (X, Y) are the random variable; lower-case (x, y) is a particular value it might take. So P(X = 7) is the probability that the sum comes out 7, and P(X \le 7) is the probability it comes out 7 or less. Getting the case right is not pedantry; it is the difference between “the rule” and “a number”.

Discrete and continuous

Random variables come in two kinds, and which one you have determines what questions are answerable.

A discrete random variable takes values you can list: 0, 1, 2, \dots. Counts are discrete. Number of sixes, number of clicks, number of defective units, number of support tickets today.

A continuous random variable takes any value in a range. Measurements are continuous. Height, time, temperature, concentration. Between any two possible values there are infinitely many others.

The line is blurrier in practice than in theory—money is technically discrete (there are only so many cents) and heights are recorded to the nearest centimetre—and that is fine. The question is never “what is it really?” but “which set of tools describes it usefully?” Salary in dollars has so many possible values that treating it as continuous is more useful than listing them.

Discrete: the probability mass function

For a discrete variable, each value carries a lump of probability. The probability mass function is the rule that says how much:

p(x) = P(X = x), \qquad \sum_x p(x) = 1

You already know how to estimate one—it is a table of proportions:

It sums to 1, because every roll produced exactly one value and they all got counted. That is not a coincidence to be checked; it is what “probability distribution” means.

The familiar triangle. Seven is the most likely total because it has the most outcomes producing it—six of the 36 pairs—while 2 and 12 have one each. The shape of a distribution comes from the process that generated it, and this is the smallest example of that principle.

Compare the pmf of Y, the number of sixes:

Three values, and their exact probabilities are 25/36, 10/36, 1/36—0.694, 0.278, 0.028. The simulation gives 0.699, 0.272, 0.028. Same 100,000 rolls, a completely different distribution, because it is a different function of the same outcomes.

The cumulative distribution function

The pmf breaks down for continuous variables, for a reason we will get to. The CDF does not, which makes it the more fundamental object:

F(x) = P(X \le x)

It is defined for every random variable of either kind, it starts at 0, it never decreases, and it ends at 1.

For a discrete variable the CDF is a staircase: flat between the possible values, jumping at each one, and the height of each jump is exactly that value’s probability mass. The picture and the pmf carry identical information.

The reason to care is that the CDF answers interval questions by subtraction:

P(a < X \le b) = F(b) - F(a)

0.6657, against the exact 24/36 = 0.6667. Every p-function you meet in the next chapter—pnorm, pbinom, ppois—is a CDF, and this subtraction is how you get an interval probability out of one.

Watch the inequality signs. F(9) - F(4) excludes 4 and includes 9. For a discrete variable that matters: P(X \le 9) - P(X \le 4) is not the same as P(X \le 9) - P(X \le 5), and off-by-one errors here are the most common source of quietly wrong probabilities in applied work. For a continuous variable it makes no difference at all, for reasons that are about to become clear.

Continuous: density instead of mass

Now the part that trips people up.

Take heights of adults, in centimetres:

Ask for the probability that someone is exactly 180 cm tall:

Zero. And not “zero because our sample is finite”—exactly zero, in the true distribution. There are infinitely many possible heights, and if every one of them carried a positive lump of probability the total would be infinite. So each individual value must carry none.

That sounds like a defeat, but it is only a redefinition. Probability for a continuous variable lives in intervals, not points:

The probability density function f(x) is what you integrate over an interval to get its probability:

P(a < X < b) = \int_a^b f(x)\,dx

so f(x) is probability per unit of x, not probability. Its units are “probability per centimetre”. A histogram with freq = FALSE is an estimate of it—bar heights scaled so that total area is 1:

A density is not a probability, and it can exceed 1

dnorm(0, mean = 0, sd = 0.1) returns about 3.99. Nothing is broken. Squeeze a distribution into a narrow range and the curve must get tall to keep the area at 1. A uniform distribution on [0, 0.5] has density exactly 2 everywhere inside it.

The practical version: read heights of a density as relative, and read areas as probabilities. Density × width ≈ probability, for a narrow enough width:

0.02283 predicted against 0.02289 counted. The density did its job; it just was not itself a probability.

The CDF, meanwhile, needs no such apology. It means the same thing for continuous variables as for discrete ones—it is simply smooth instead of a staircase:

And the interval rule is unchanged:

0.1068 against 0.1056. That is the entire relationship between a simulation and a formula: same question, two ways of answering it, and if they disagree by more than noise you have found a bug in one of them.

Density versus probability

A continuous random variable X has probability density f(0.3) = 2.4.

Which statement is correct?

Densities have units of probability per unit of x, not probability. Squeeze a distribution into a narrow range and the curve has to get tall to keep the total area at 1. A uniform distribution on [0, 0.5] has density exactly 2 everywhere inside that interval; dnorm(0, mean = 0, sd = 0.1) in R returns about 3.99. Neither is a bug.

For a continuous variable, P(X = 0.3) = 0 exactly—there are uncountably many values it could take and no single one carries any mass. That sounds like a technicality until you meet it in practice: mean(x == 0.3) on a sample of continuous measurements returns 0, and it always will. What you can ask for is P(0.29 < X < 0.31), which is an area, roughly f(0.3) \times 0.02 = 0.048.

The third option describes something a density nearly does—the curve being higher at 0.3 than at some other point does mean values land near 0.3 more often than near that point—but “2.4 times as often as any other value” is not what the number 2.4 says. The height is only comparable to other heights of the same density, not to 1, and never to a count.

The practical rule: read heights of a density as relative, and read areas as probabilities. The function that gives you areas directly is the CDF, and in R that is pnorm, punif, pbinom, and their relatives.

What comes next, and why

You now have a distribution: a complete description of what values a random variable takes and how often. A complete description is often too much description. Eleven numbers for the dice sum, a whole curve for heights—you cannot put that in a sentence, and you cannot compare two of them at a glance.

So next week compresses a distribution into two numbers:

  • Expectation, E[X]—the long-run average value, the balance point of the distribution. It is the mean from Describing a Single Variable, promoted from a fact about a sample to a property of the process that generated it.
  • Variance, \operatorname{Var}(X)—how far the variable typically strays from its expectation.
Why The Standard Error of a Mean is the hinge of this course

Those two summaries would be mildly useful on their own. What makes them the center of the term is a single fact about how they combine:

For independent random variables, variances add.

Everything downstream follows from that one line. Apply it to a sample mean \bar X and you get \operatorname{Var}(\bar X) = \sigma^2/n, so the standard deviation of a sample mean is \sigma/\sqrt{n}—the standard error. That formula is why bigger samples are better, exactly how much better, and by what rate. Confidence intervals are built on it. So are p-values, sample-size calculations, and every A/B test you will ever run.

Notice the word independent in the statement. That is the concept from Probability, and it is load-bearing: when observations are not independent—repeat visits from the same user, students within a classroom, days within a week—\sigma/\sqrt{n} is wrong, your interval is too narrow, and you are more confident than the data entitles you to be. This is one of the most common real errors in applied statistics, and by The Standard Error of a Mean you will be able to say exactly which step it breaks.

We are not deriving any of that here. Arrive next week solid on two things and it will be a short evening: a random variable is a function of a random outcome, and independence means P(A \cap B) = P(A)P(B).

Exercise: a different function of the same rolls

mean(abs(d1 - d2) == 0)

Or simply mean(d1 == d2). The exact value is 6/36 = 1/6 \approx 0.1667.

Exercise: reading a CDF

Fx(9) - Fx(4)

About 0.6657. For an integer-valued variable, “at least 5” means “not at most 4”, so the subtraction point is 4 and not 5. The same off-by-one shows up whenever you use pbinom or ppois for a tail probability.

Exercise: a tail probability for a continuous variable

mean(h > 185)

About 0.031, and pnorm(185, 170, 8, lower.tail = FALSE) gives 0.0304.

Exercise: which kind of variable

answer <- "A"

Counts and yes/no outcomes are discrete; times and measurements are continuous. The binary case is worth flagging because it is the one people forget: TRUE and FALSE are a perfectly good random variable, and treating them as 1 and 0 is what lets mean() compute a probability.

Summary

  • A random variable is a function from outcomes to numbers. The rule is fixed; only the outcome is random. Several different random variables can be defined on the same outcomes, and the same simulation supports all of them.
  • Discrete variables take listable values (counts, categories, 0/1); continuous ones take any value in a range (times, measurements).
  • The probability mass function p(x) = P(X = x) describes a discrete variable, and table(x) / length(x) estimates it.
  • For a continuous variable P(X = x) = 0 for every x. Probability lives in intervals, described by a density f(x) whose area is the probability. Densities are not probabilities and may exceed 1.
  • The CDF F(x) = P(X \le x) works for both kinds, and interval probabilities are F(b) - F(a). Mind the endpoints for discrete variables.
  • Next week: expectation and variance, and the fact that variances of independent quantities add—which gives \operatorname{Var}(\bar X) = \sigma^2/n and everything built on it.

Next, though: the handful of distributions that describe most of the data you will ever meet, and how to tell which one you are looking at.
